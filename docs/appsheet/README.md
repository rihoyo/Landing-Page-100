# 상담 접수 관리 대시보드 — AppSheet 설정 안내

이 문서는 현재 실제 접수 데이터 구조에 맞춘 앱 설정안입니다. AppSheet 앱 자체는 아직 생성되지 않았습니다. 별도의 공개 HTML 홈페이지를 만들지 않고 AppSheet가 제공하는 로그인 가능한 웹 앱 주소로 사용합니다.

## 1. 연결할 데이터

- 문서: https://docs.google.com/spreadsheets/d/1ME5SZBoiaKSQRlnuHxkO_7-4HtM_KqMf8HwnW5fvOdk/edit
- 원본 탭: `상담신청 테스트`
- AppSheet 테이블 이름: `접수` (아래 식은 이 이름을 기준으로 합니다)
- 사용 목적: 통계, 검색, 조건별 상담 목록
- 원본 테이블 업데이트: `READ_ONLY`
- Key: `요청번호` / Label: `이름`

문서나 원본 탭의 이름·열 순서를 바꾸지 않습니다. AppSheet 안의 테이블 이름만 `접수`로 설정합니다. 원본은 시트와 Apps Script에서 계속 추가됩니다.

## 2. 최초 앱 생성

1. https://www.appsheet.com 에 시트 접근 권한이 있는 계정으로 로그인합니다.
2. `Create → App → Start with existing data`를 선택합니다.
3. 앱 이름을 `상담 접수 관리`로 입력하고 Google Sheets 문서와 원본 탭을 연결합니다.
4. `Data → Tables`에서 테이블 이름을 `접수`로 설정하고 업데이트 허용을 `READ_ONLY`로 지정합니다.
5. 아래 열 형식과 로그인 설정을 적용합니다.

메뉴 위치와 명칭은 편집기 버전에 따라 달라질 수 있습니다. 테이블 추가, Columns, Slices, Views, User Settings는 편집기 검색으로 찾을 수 있습니다.

## 3. 데이터 형식

| 열         | 형식     | 설정                                                           |
| ---------- | -------- | -------------------------------------------------------------- |
| 접수시간   | DateTime | `2026-10-11 09:00:00` 같은 기존 문자열을 정상 해석하는지 확인  |
| 요청번호   | Text     | Key 켜기. 모든 기존 행에서 값이 있고 고유해야 함               |
| 랜딩번호   | Text     | aa0001, aa0002, aa0003 등                                      |
| 이름       | Text     | Label 켜기                                                     |
| 연락처     | Phone    | 앞자리 0 유지 확인                                             |
| 생년월일   | Text     | YYYYMMDD 형식이므로 자동 Date 변환하지 않음                    |
| 나이       | Number   | 기존 텍스트 숫자도 정상 해석하는지 확인                        |
| 성별       | Text     | 남자/여자                                                      |
| 상담시간   | Text     | 희망 상담 시간                                                 |
| 연령대     | Text     | 비어 있어도 무방함                                             |
| 관심상품   | Text     | 현재는 쉼표로 합친 문자열, 다중 선택 통계는 별도 분해가 필요함 |
| 문의내용   | LongText | 상세 화면에 표시                                               |
| 동의여부   | Text     | 동의 기록                                                      |
| 유입소스   | Text     | 광고 소스                                                      |
| 유입캠페인 | Text     | 광고 캠페인                                                    |
| 주거지역   | Text     | 서울/경기 등                                                   |

앱 로케일·시간대 설정을 확인하고 한국 날짜 기준으로 접수시간과 TODAY()가 해석되는지 점검합니다. 접수시간을 잘못 해석한 상태에서 날짜 필터를 먼저 적용하면 행이 빠질 수 있습니다.

가상 열(Virtual column) `접수일`을 추가합니다. Type은 Date, App formula는 다음과 같습니다. 가상 열은 원본 시트에 새 열을 만들지 않습니다.

```appsheet
DATE([접수시간])
```

## 4. 맞춤 필터 — User Settings

`User Settings`에서 다음 항목을 만듭니다. 저장한 조건은 해당 사용자의 기기·브라우저 설정입니다. 보안 권한을 대신하지 않습니다.

| 설정 이름 | 형식                 | 초기값 또는 선택값            |
| --------- | -------------------- | ----------------------------- |
| 시작일    | Date                 | Initial value: `TODAY() - 29` |
| 종료일    | Date                 | Initial value: `TODAY()`      |
| 랜딩선택  | Enum, base type Text | Initial value: `"전체"`       |
| 지역선택  | Enum, base type Text | Initial value: `"전체"`       |
| 최소나이  | Number               | 비워 둠                       |
| 최대나이  | Number               | 비워 둠                       |

`랜딩선택`의 Valid If:

```appsheet
LIST("전체") + SORT(UNIQUE(접수[랜딩번호]))
```

`지역선택`의 Valid If:

```appsheet
LIST("전체") + SORT(UNIQUE(SELECT(접수[주거지역], ISNOTBLANK([주거지역]))))
```

`종료일`의 Valid If:

```appsheet
OR(ISBLANK([_THIS]), ISBLANK(USERSETTINGS("시작일")), [_THIS] >= USERSETTINGS("시작일"))
```

`최대나이`의 Valid If:

```appsheet
OR(ISBLANK([_THIS]), ISBLANK(USERSETTINGS("최소나이")), [_THIS] >= USERSETTINGS("최소나이"))
```

## 5. 맞춤 목록 — Slice

`Data → Slices`에서 Source table `접수`, 이름 `필터된접수`로 생성합니다.

Row filter condition에는 [filtered-receipts.txt](filtered-receipts.txt)의 내용을 전체 복사합니다. 동작은 다음과 같습니다.

- 기간·랜딩·지역·최소나이·최대나이를 동시에 적용합니다.
- 날짜나 나이를 비워두면 해당 조건을 적용하지 않습니다.
- 나이 조건을 지정했을 때만 나이 없는 신청을 제외합니다.
- 시작일과 종료일 모두 포함합니다.

추가 Slice `오늘접수`:

```appsheet
[접수일] = TODAY()
```

오늘접수는 날짜를 바꿔도 오늘 날짜를 기준으로 합니다. 필터 조건을 적용한 통계는 모두 `필터된접수`를 사용합니다.

## 6. 화면 구성

`Views`에서 다음 화면을 생성합니다. 예전 편집기에서는 `UX → Views`에 있습니다.

| 화면 이름     | 데이터     | View type | 설정                                   |
| ------------- | ---------- | --------- | -------------------------------------- |
| 전체 상담     | 접수       | Table     | 접수시간 내림차순, 검색 켜기           |
| 맞춤 상담     | 필터된접수 | Table     | 접수시간 내림차순                      |
| 오늘 상담     | 오늘접수   | Table     | 접수시간 내림차순                      |
| 일별 접수     | 필터된접수 | Chart     | 접수일별 그룹, 요청번호 Count 집계     |
| 랜딩별 접수   | 필터된접수 | Chart     | 랜딩번호별 그룹, 요청번호 Count 집계   |
| 지역별 접수   | 필터된접수 | Chart     | 주거지역별 그룹, 요청번호 Count 집계   |
| 캠페인별 접수 | 필터된접수 | Chart     | 유입캠페인별 그룹, 요청번호 Count 집계 |
| 접수 상세     | 접수       | Detail    | 개인정보는 목록보다 상세 화면에 배치   |

Table의 목록 표시 순서는 `접수시간 → 이름 → 연락처 → 랜딩번호 → 주거지역 → 나이`를 권장합니다.

차트는 그룹별 **행 수/Count**를 집계해야 합니다. 나이 합계나 전화번호 개수를 값으로 선택하지 마세요. 차트 설정 화면에 맞춰 그룹 열과 Count 집계 열을 지정하고, 원본 수와 일치하는지 확인합니다.

Dashboard View `접수 대시보드`를 추가하고 `맞춤 상담`, `일별 접수`, `랜딩별 접수`, `지역별 접수`를 포함합니다. Interactive mode를 켜면 지원하는 차트·목록 간 선택 연동을 사용할 수 있습니다. 실제 연동 여부는 미리보기에서 확인합니다.

앱 시작 화면은 `접수 대시보드`로 지정합니다. AppSheet 자체 User Settings 화면에서 조건을 바꾸고 돌아오면 목록과 차트에 같은 필터가 적용됩니다. 이 방식은 일반 웹사이트처럼 필터 입력칸이 대시보드 위에 항상 표시되는 UI는 아닙니다.

## 7. 로그인과 공유

확정한 권한은 **관리자는 전체 접수·통계, 직원은 담당 접수·통계만 조회**입니다. 미배정 신규 접수는 관리자에게만 표시합니다.

직원 공동 사용은 [직원 권한 및 담당자 설정](staff-access.md)을 함께 적용합니다. 사용자권한·상담관리 탭의 제목 행 템플릿도 포함되어 있습니다.

- `Security → Require sign-in`을 켭니다.
- 본인용은 본인 계정만 허용합니다. 직원용은 승인한 직원 이메일만 공유 대상으로 등록합니다.
- Google 시트 자체를 인터넷 전체 공개로 바꾸지 않습니다.
- 직원마다 담당 접수만 보여줘야 한다면 Security Filter와 담당자·권한 구조가 추가로 필요합니다. Slice만으로 개인정보 접근을 차단할 수 없습니다.
- 제작·테스트와 운영 배포의 라이선스 조건은 다릅니다. AppSheet 구독 또는 Google Workspace에 포함된 라이선스를 계정에서 확인합니다.

## 8. 상담 상태 관리 확장

조회 화면을 먼저 완성한 다음 별도 탭 `상담관리`를 연결하는 방식으로 확장합니다.

| 열       | 형식            | 역할                                   |
| -------- | --------------- | -------------------------------------- |
| 요청번호 | Ref → 접수      | Key, 원본 신청과 1:1 연결              |
| 담당자   | Email           | 담당 직원                              |
| 상담상태 | Enum            | 신규 / 연락중 / 상담완료 / 부재 / 취소 |
| 상담메모 | LongText        | 내부 메모                              |
| 수정시간 | ChangeTimestamp | 관리 데이터 변경 시간                  |

상담관리 테이블만 수정 가능하게 하고 원본 접수는 조회 전용을 유지합니다. 이 탭을 연결한다고 기존 접수별 관리 행이 자동 생성되지는 않습니다. 새 관리 행 생성 액션이나 별도 자동화가 필요합니다. Apps Script의 직접 시트 쓰기가 AppSheet 이벤트 봇을 반드시 실행시키는 것은 아니므로 트리거를 검증한 후 사용합니다.

관리 행 연결 후 담당자별 권한과 상태별 목록을 추가할 수 있습니다. 여러 직원의 역할·공유 범위를 결정한 뒤 구현해야 합니다.

## 9. 완성 확인

1. 전체 상담의 행 수가 시트와 일치하는지 확인합니다.
2. 요청번호를 검색하여 이름·연락처·접수시간이 맞는지 확인합니다.
3. 기간과 aa0003 조건을 설정해 목록과 차트가 동일한 범위를 사용하는지 확인합니다.
4. 원본 상담을 AppSheet에서 수정·삭제할 수 없는지 확인합니다.
5. 허용하지 않은 계정이 앱을 열 수 없는지 확인합니다.
6. 새 랜딩 신청 후 Sync로 새 행이 나타나는지 확인합니다. 시트에 추가된 행이 앱에 즉시 표시된다고 가정하지 않습니다.
7. 배포 검사에서 권한·라이선스·데이터 경고를 확인한 뒤 앱 웹 주소를 공유합니다.
