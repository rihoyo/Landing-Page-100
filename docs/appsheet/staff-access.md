# 직원과 함께 사용하는 앱 설정

확정한 운영 방침은 **관리자는 전체, 직원은 담당 건만 조회**입니다. 아래 설정은 이 방침을 적용합니다. 앱은 로그인 필수, 승인한 이메일만 공유하며 시트 원본을 직원 전체에 직접 공유하지 않는 구성을 권장합니다.

## 1. 원본 접수와 별도로 관리 탭 만들기

접수 문서에 다음 두 탭을 만듭니다. 원본 `상담신청 테스트`는 변경하지 않습니다.

- `사용자권한`: [users.tsv](users.tsv)를 A1에 붙여넣습니다.
- `상담관리`: [management.tsv](management.tsv)를 A1에 붙여넣습니다.

AppSheet에 두 탭을 추가하고 테이블 이름도 동일하게 지정합니다.

`사용자권한`의 이메일을 Email+Key, 역할을 Enum(관리자/직원), 활성여부를 Yes/No로 설정합니다. 본인 Google 계정 이메일을 관리자·활성 TRUE로, 승인할 직원 계정을 직원·활성 TRUE로 입력합니다. 이 테이블은 READ_ONLY로 하여 AppSheet에서 직원이 자신의 역할을 바꾸지 못하게 합니다. 역할 변경은 관리자가 원본 시트에서 수행합니다.

`상담관리`의 요청번호를 Ref → 접수 + Key, 담당자를 Email, 상담상태를 Enum(신규/연락중/상담완료/부재/취소), 상담메모를 LongText, 수정시간을 ChangeTimestamp로 설정합니다.

## 2. 공통 권한 확인식

활성 계정인지 확인:

```appsheet
LOOKUP(USEREMAIL(), "사용자권한", "이메일", "활성여부") = TRUE
```

관리자인지 확인:

```appsheet
LOOKUP(USEREMAIL(), "사용자권한", "이메일", "역할") = "관리자"
```

앱 공유 이메일 목록과 사용자권한 테이블을 함께 관리합니다. 계정을 해제한 뒤 사용자에게 동기화를 요구하거나 앱 공유 권한도 회수합니다. 이미 기기에 동기화된 데이터를 즉시 원격 삭제할 수 있다고 가정하지 않습니다.

`사용자권한` 테이블의 Security Filter는 아래처럼 지정하여 각 사용자가 자신의 권한 행만 내려받게 합니다.

```appsheet
[이메일] = USEREMAIL()
```

## 3. 관리자는 전체, 직원은 담당 건만

`접수` 테이블의 Security Filter:

```appsheet
AND(
  LOOKUP(USEREMAIL(), "사용자권한", "이메일", "활성여부") = TRUE,
  OR(
    LOOKUP(USEREMAIL(), "사용자권한", "이메일", "역할") = "관리자",
    IN(
      [요청번호],
      SELECT(상담관리[요청번호], [담당자] = USEREMAIL())
    )
  )
)
```

`상담관리` 테이블의 Security Filter:

```appsheet
AND(
  LOOKUP(USEREMAIL(), "사용자권한", "이메일", "활성여부") = TRUE,
  OR(
    LOOKUP(USEREMAIL(), "사용자권한", "이메일", "역할") = "관리자",
    [담당자] = USEREMAIL()
  )
)
```

담당자가 없는 새 접수는 관리자에게만 보입니다. 관리자가 상담관리 행을 만들고 요청번호와 담당자를 지정해야 담당 직원에게 나타납니다. 직원 화면의 통계도 담당 접수만 집계됩니다.

## 4. 담당자 지정과 메모 수정

원본 접수 테이블은 READ_ONLY를 유지합니다.

`상담관리`의 Are updates allowed?에 다음 식을 사용하면 관리자는 행을 추가·수정·삭제하고 직원은 기존 관리 행만 수정할 수 있습니다.

```appsheet
IF(
  LOOKUP(USEREMAIL(), "사용자권한", "이메일", "역할") = "관리자",
  "ALL_CHANGES",
  "UPDATES_ONLY"
)
```

상담관리의 `요청번호`, `담당자` 열 Editable_If는 관리자 확인식으로 설정합니다. 직원에게 배정·변경 권한을 주지 않는 구성입니다.

`상담상태`, `상담메모` 열 Editable_If:

```appsheet
OR(
  LOOKUP(USEREMAIL(), "사용자권한", "이메일", "역할") = "관리자",
  [담당자] = USEREMAIL()
)
```

관리자는 새 관리 행에 기존 접수 요청번호를 골라 담당자를 배정합니다. Ref의 Label을 이름만 사용하면 동명이인이 헷갈릴 수 있으므로 상세의 요청번호·접수시간·연락처로 대상 신청을 확인합니다. 기존 접수 목록에서 관리 행을 생성하는 액션은 이후 추가할 수 있습니다.

## 5. 권한 테스트

1. 관리자 계정에서 모든 접수와 미배정 접수가 보이는지 확인합니다.
2. 직원 A·직원 B 계정에 각각 다른 접수를 배정합니다.
3. 관리자는 전체, 직원은 담당 건만 보이는지 각 계정으로 로그인하여 확인합니다.
4. 검색·상세·차트·Ref 선택에서도 다른 직원 건이 노출되지 않는지 확인합니다.
5. 직원이 사용자권한·요청번호·담당자 값을 수정하지 못하는지 확인합니다.
6. 비활성 계정과 초대하지 않은 계정의 접근을 확인합니다.

Security Filter를 제공하는 라이선스와 실제 사용자 라이선스를 현재 AppSheet 계정에서 확인한 뒤 운영 배포합니다. 로그인, 데이터 필터, 수정 조건을 각각 테스트해야 하며 화면 미리보기만으로 접근 제어 완료라고 판단하지 않습니다.
