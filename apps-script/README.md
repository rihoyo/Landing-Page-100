# 상담 접수 공통 수신 서버 업데이트

GitHub Pages와 Google Apps Script는 별도로 배포됩니다. 실제 수신 API에 같은 입력을 보내고 랜딩 번호만 바꿔 확인한 결과, aa0001은 성공하고 aa0003은 입력 오류로 거부되었습니다. 편집기에 aa0003을 허용하는 코드를 저장했더라도 기존 웹 앱 배포를 새 버전으로 업데이트해야 반영됩니다. version 값만으로 허용 목록을 판단할 수는 없습니다.

## 기존 배포를 한 번만 업데이트

1. 접수 스프레드시트를 Google 계정으로 열고 **확장 프로그램 → Apps Script**를 누릅니다.
2. 이 저장소의 [Code.gs](Code.gs) **전체 내용**으로 Apps Script 편집기의 Code.gs 내용을 교체한 뒤 저장합니다. 기존 스프레드시트 ID와 시트 이름은 보존되어 있습니다.
3. 오른쪽 위 **배포 → 배포 관리**에서 현재 사이트가 사용하는 기존 웹 앱 배포를 선택하고 연필 버튼을 누릅니다.
4. 버전을 **새 버전**으로 선택합니다. 실행 사용자는 **나**, 액세스 권한은 **모든 사용자**인지 확인하고 **배포**합니다. 새로운 별도 배포를 만들지 말고 기존 배포를 업데이트해야 URL이 유지됩니다.
5. [현재 수신 API](https://script.google.com/macros/s/AKfycbxSrv2QHh4t354p704j8bENmZfngHq2dcWFvmBV29DOg9D_fYlsS7mWf44Ph6o9-91f/exec)를 열어 `version: 2`가 표시되는지 확인합니다. 이후 aa0003에서 테스트 신청 한 건을 보내고 시트의 랜딩번호·주거지역·연락처가 저장되었는지 확인합니다.

이 환경에는 Google Apps Script 편집/배포 계정 연결이 없어 위 업데이트는 해당 Google 계정에서 해야 합니다. GitHub 커밋 또는 Pages 재배포만으로 수신 서버가 바뀌지 않습니다.

## 모든 랜딩의 공통 계약

- 모든 페이지가 `useConsultationForm` → `src/lib/sheets.ts` → 동일한 Apps Script 수신 서버를 사용합니다.
- `page_id`는 `aa0001`부터 `aa9999`까지 같은 형식으로 처리합니다. `aa0000`, `aa/0003`, 임의 문자열은 거부합니다. 새 번호 추가를 위해 서버를 다시 배포할 필요가 없습니다.
- v2는 기존 15개 열을 유지하고 마지막에 **주거지역** 열을 추가합니다. 기존 행과 데이터는 덮어쓰지 않습니다.
- 요청번호는 저장 확인 후 캐시에 등록합니다. 반복 접수는 캐시로 확인하고, 캐시가 만료되어도 시트에서 같은 요청번호를 확인해 중복 저장하지 않습니다. 개인정보는 캐시에 저장하지 않습니다.
- 이름·연락처·생년월일·필수 동의 검증과 시트 수식 삽입 방어를 유지합니다.
- 성공 JSON과 요청번호가 확인된 경우에만 프런트엔드가 접수 완료를 표시합니다. `no-cors`로 오류를 숨기거나 다른 랜딩 번호로 위장하지 않습니다.

## 설정할 곳과 랜딩 번호의 의미

`Code.gs` 맨 위의 **1. 운영자가 수정하는 설정**에서 저장 위치를 변경합니다.

| 설정             | 의미                                                        |
| ---------------- | ----------------------------------------------------------- |
| `SPREADSHEET_ID` | 기본 Google Sheets 문서 ID                                  |
| `SHEET_NAME`     | 기본 문서 안의 탭 이름                                      |
| `STORAGE_ROUTES` | 랜딩 번호 범위별 다른 저장 위치. 빈 배열이면 전부 기본 위치 |
| `HEADERS`        | 저장할 열의 제목과 순서. 기존 데이터가 있으면 순서를 유지   |

`/^aa(?!0000$)\d{4}$/`는 **aa 뒤에 숫자 4자리가 오되 0000은 제외**하는 형식 검사입니다. `aa0001`~`aa9999`를 허용하고 `aa0000`, `aa/0003`, `AA0003`을 거부합니다. 이 식은 저장 위치를 선택하지 않습니다.

| 부분        | 뜻                               |
| ----------- | -------------------------------- |
| `^`         | 문자열 시작                      |
| `aa`        | 소문자 aa                        |
| `(?!0000$)` | 남은 부분이 정확히 0000이면 거부 |
| `\d{4}`     | 숫자 4자리                       |
| `$`         | 문자열 끝                        |

## 번호 범위별로 저장 위치 나누기

예를 들어 아래처럼 `STORAGE_ROUTES`를 설정합니다. **예시는 기본적으로 비활성화되어 있습니다.**

```js
const STORAGE_ROUTES = [
  { from: 3, to: 20, sheetName: '건강보험 상담' },
  { from: 21, to: 50, spreadsheetId: '다른_문서_ID', sheetName: '별도 상담' },
];
```

- `aa0003`~`aa0020`: 기본 문서의 **건강보험 상담** 탭.
- `aa0021`~`aa0050`: 지정한 다른 문서의 **별도 상담** 탭.
- 나머지 번호: 기존 기본 문서·탭.

양끝 번호도 포함합니다. 없는 탭은 자동 생성하며, 다른 문서 자체는 미리 만들어 두어야 합니다. 웹 앱 실행 계정에 해당 문서의 편집 권한이 필요합니다. 범위가 겹치거나 잘못된 설정이면 오류를 반환하며 아무 행도 쓰지 않습니다.

설정 변경 후에는 기존 웹 앱 배포를 새 버전으로 업데이트해야 합니다. 변경 이후 접수부터 적용되며 기존 행은 이동하지 않습니다. 저장 위치 변경 후 같은 요청을 다시 전송하면 새 위치에 저장될 수 있습니다. 중복 확인은 선택된 시트를 기준으로 합니다.

## 함수별 짧은 설명

코드 안의 `[1]`~`[16]` 주석 번호와 대응합니다.

| 번호 | 함수              | 하는 일                                          |
| ---- | ----------------- | ------------------------------------------------ |
| 1    | `doGet`           | API 상태를 보여줌. 저장하지 않음                 |
| 2    | `doPost`          | 신청 검사·중복 확인·저장·응답의 전체 순서를 실행 |
| 3    | `readSubmission`  | 이름, 연락처, 날짜, 동의 등 입력 검사            |
| 4    | `selectStorage`   | 랜딩 번호에 맞는 저장 문서·탭 선택               |
| 5    | `openSheet`       | 문서를 열고 탭을 찾거나 생성                     |
| 6    | `prepareHeaders`  | 열 제목 검사, 필요하면 주거지역 열 추가          |
| 7    | `alreadySaved`    | 요청번호가 이미 시트에 있는지 확인               |
| 8    | `writeSubmission` | 신청을 새 행 하나로 저장                         |
| 9    | `requestCache`    | 빠른 중복 확인용 캐시 연결                       |
| 10   | `cachedRequest`   | 같은 저장 위치에 성공한 요청인지 캐시 확인       |
| 11   | `rememberRequest` | 성공한 요청번호·저장 위치를 최대 6시간 기억      |
| 12   | `safeCell`        | 수식 실행 방지, 셀 글자 수 제한                  |
| 13   | `serverAge`       | 생년월일 검사 및 만 나이 계산                    |
| 14   | `receipt`         | 성공 및 중복 접수 응답 생성                      |
| 15   | `failureResponse` | 실패 원인을 이해하기 쉬운 메시지로 변환          |
| 16   | `jsonResponse`    | 홈페이지가 읽을 JSON 응답 전송                   |

캐시는 조기에 사라질 수 있으므로 시트 검색도 유지합니다. 저장이 확인된 요청만 캐시에 기록하며, 이름·연락처·문의내용은 캐시에 넣지 않습니다.
